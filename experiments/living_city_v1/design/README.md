# 活街区 01：传统 2D 灰盒坐标合同

**状态：关卡结构试验；视觉验收未通过。** `street_block_01.json` 是关卡空间、镜头、图层、路线和目标归属的唯一手写数据源。`tools/sync_street_block.mjs` 从它生成 Cocos 城市配置与运行时 JSON 副本。预览 PNG 和运行时彩色几何块都是诊断图，不是可用美术，也不表示贴图感已解决。

## 坐标与镜头

- 地图 `1536×2048` 世界单位，中心 `(0,0)`，向右 `+X`，向上 `+Y`。NPC 节点原点为两脚之间的接地点。美术槽 `center/size` 是独立图层的最终游戏世界尺寸，不是图像生成画布或源文件像素承诺。
- Cocos 旧 `CityConfig` 的实体位置用左下角归一化坐标。同步脚本显式换算：`xNorm=(x+768)/1536`，`yNorm=(y+1024)/2048`。不可把蓝图的世界坐标直接写入 `city.json` 的 `x/y`。
- 444×960 屏幕以 `cover-fit=max(444/1536,960/2048)=0.46875` 映射。普通视图 `1.4×` 后是 `0.65625` 屏幕像素/世界单位，视域约 `677×1463` 世界单位；镜头中心 `(-150,20)`。120 世界单位高的小鸡约 79 屏幕像素。最大 `2.25×` 后是 `1.0547` 屏幕像素/世界单位，小鸡约 127 像素；细节预览中心 `(-295,350)`。
- 首屏下方 156 屏幕像素留给任务栏。预览据此遮盖可用画面；实际 Cocos HUD 须在运行截图中复核。

## 空间及图层

四块相交的公共可走多边形组成主街、横巷、茶摊顾客短支路和东侧市集。茶摊柜台实体是 `x=-363..-333, y=285..425`；摊主脚点 `(-410,350)`，顾客脚点 `(-285,350)`，杯子交接点 `(-340,382)`。顾客与柜台之间保留 48 世界单位，双角色站位不靠移进道具碰撞区来凑画面。摊主位于单独 `vendor_only` 区。

渲染次序为地面、店面后层、街面后层、按脚点 `Y` 从大到小排序的角色/矮道具、屋檐与横幅上层、独立特效。柜台前层脚线是 `Y=284`，因此会挡住摊主 `Y=350` 的下身；顾客在柜台右边，不被整块前层吞掉。`physicalFootprints` 是地面阻挡；上方横幅和旗串无地面碰撞。

`npcPlans` 的几何 marker 只验证人和道具是否站得下。信使从 `(-100,-300)` 沿街走到顾客脚点，茶摊事件停留 1.9 秒，随后北行；另一名购物者用较慢、带停留的路线活动。摊主递杯、望灯者招手、栗子摊主动作目前均为灰盒节拍提示。正式角色动作需要手绘的同源分层或连续逐帧源文件，不能由这些几何圆块转正。

四个 `hiddenObjectSlots` 分别附着茶柜、裁缝货架、横幅和栗子车。格局上前三个在首屏且位于 HUD 外，栗子车在东侧平移后可找到。蓝色小圆是调试点击位置；正式美术必须把物品画进承托面附近、控制局部遮挡和色差，再在普通/最大放大及真机上复核可发现性。

## 验证命令和产物

在本独立工程运行：

```powershell
node tools/validate_street_block.mjs
node tools/sync_street_block.mjs
python tools/render_street_block_preview.py
```

`validate_street_block.mjs` 检查坐标边界、ID、连通公共区、图层槽、所有 NPC 路段每 10 单位采样的足部净空、物品支撑关系、交接站位和 444×960 相机可见性。它不能替代 Cocos 触控与视觉审查。

## 仍未通过的视觉门槛

- 中央主街即使增加少量街沿细节，普通视图仍显空；目前的方块和圆点没有任何可认可的城市绘画密度。不能把“有四个位置标记”记为活动角色已可读。
- 三个首屏寻物标记仅约 17–20 屏幕像素，裁缝目标靠近底部 HUD；机械可点击不等于玩家可以自然找到。
- 角色母版、两脚接地的动作、柜台递杯同源帧、四店铺和街沿的正式分层水彩素材均未制作或验收。

因此运行版只用于确认空间合同与交互输入。视觉方向仍需先做手绘分层小样，在实机尺寸连续回放中通过，才替换这些占位形状。
