# 信使鸡：传统 2D 逐帧美术制作规格

**状态：制作模板完成，角色设计与任何动画帧均未获批、未绘制、未进入游戏。** 本文件只适用于独立工程 `experiments/living_city_v1/`。旧试玩版的资产与构建不由本规格改动。

## 依据与设计边界

- 唯一已获用户认可的画风方向是 `art/reference/chicken_cast_style_guide_v1.png`；它不授权照搬图中某只鸡、衣服或表情。完整视觉语言见根项目 `docs/ART_BIBLE.md`，输出精度和 Alpha 原则见 `docs/ASSET_SPEC.md`。
- `art/generated/chicken_rig_001/young_adult_canonical_candidate_02.png` 只是 **review 状态的造型讨论图**。它在 79 px 下比第一只大眼幼鸡更能辨认衣装，但翅、腿、头、背心和包烘焙在一张图里，还带细碎羽毛与边缘色。不得裁开假装分层、导入运行时、或记为已获批母版。
- 本角色是街区里的年轻成年信使/顾客。不会替代规范里尚待审核的无服饰幼鸡母版。画师须原创重画，而非沿用候选图的像素。

## 与关卡的空间合同

| 项目 | 数值 / 规则 |
| --- | --- |
| 地图 | `1536×2048` 世界单位的近俯视、近似平行投影街区；屋顶和短立面可见 |
| 摄像机 | 初始约 `0.656` 屏幕像素 / 世界单位，常态角色约 `79 px` 高，最大缩放约 `127 px` |
| 角色尺寸 | 从脚接地点到鸡冠顶 `120` 世界单位；第一版正面/背面/侧面保持同一高度与身体体积 |
| 地面原点 | 两足接地区域的中点；场景坐标 `+X` 向右、`+Y` 向上，角色原点绝不放在图片中心 |
| 事件路线 | 起点 `(-100,-300)`，经 `(-130,-150)`、`(-130,80)`、`(-210,210)`，在茶摊顾客点 `(-285,350)` 停下，向左看摊主 `(-410,350)`，再经 `(-220,500)`、`(-145,700)` 离开 |

画面角度必须让脚踩在街面，向北走时可见头顶、后颈、尾与包背；向左接杯时可看见喙、眼、近翼。不能拿正面肖像图横向平移代替这些方向。道具杯由关卡独立层控制；角色接杯帧只画伸出的翼/爪，杯子不能烘焙进每帧。

## 画师源文件与游戏导出

| 项目 | Generation / authoring spec | Final game asset spec |
| --- | --- | --- |
| 每帧画布 | `512×512 px`，RGBA，统一画布；可在 Krita 等支持 OpenRaster 的软件打开 `.ora` 模板并另存逐帧文件 | `256×256 px` RGBA PNG，每帧同画布、不逐帧自动裁切 |
| 注册点 | 源文件 `(256,430)`，从左上角计；鸡冠顶约 `y=70`，因此可见高约 `360 px` | 导出后 `(128,215)`；Cocos 锚点 `anchorX=0.5`、`anchorY=41/256≈0.16015625` |
| 显示比例 | 先按 50% 统一缩图，不单独拉伸各姿势 | `180` 可见素材像素映射到 `120` 世界单位，Sprite 缩放 `2/3`；常态约 `79` 屏幕像素 |
| 透明与光影 | 真 Alpha；纸纹/颜料只在角色轮廓内；画布外保持透明 | PNG 边缘无棕/红/黄色晕；地面接触阴影由关卡独立层绘制或渲染，不烘焙进鸡 |
| 色彩与线条 | 奶油黄与麦金羽毛，灰蓝布料、赭红小包；左上柔光；暖棕不匀线稿 | 79 px 下眼约 1–2 屏幕像素、脚/喙及包的主形可辨；外轮廓不会随帧忽粗忽细 |

`art/production/courier_chicken_v1/courier_turnaround_template.ora` 是 **2048×512 的空白四视图设定模板**，四个 512 px 分格共享同一脚线。先在这里定 N、NW、NE、W 四视图。`courier_frame_template.ora` 是**空白逐帧绘画模板**：可编辑的头、翼、腿、身躯、服饰层，加一层地面原点和安全边界引导。使用时复制为 `frame_inventory.csv` 指定的每个 `.ora` 源文件，在绘画软件里逐帧绘制并以洋葱皮/叠帧对齐。导出前隐藏 `GUIDE_registration_HIDE_BEFORE_EXPORT` 层，再导出同名 `.png`。OpenRaster 保留普通图层；它不替代 Krita 原生动画时间轴。需要时间轴时，可将完成的逐帧 PNG 导入时间轴继续精修。

## 动画镜头与帧清单

完整 ID、文件名、建议时长与画面任务见 `art/production/courier_chicken_v1/frame_inventory.csv`，共 **36 张手绘帧**：

| 动作 | 帧 | 用途 |
| --- | ---: | --- |
| `walk_n` | 6 | 北向背面，覆盖长直路 |
| `walk_nw` | 6 | 朝茶摊的西北 3/4 背面 |
| `walk_ne` | 6 | 离开的东北 3/4 背面；包的位置必须在身体同一侧，不能直接镜像 `walk_nw` |
| `turn_nw_w` | 4 | 到站后的头领先转向，脚原地换支撑 |
| `idle_w` | 4 | 呼吸、观察、一次眨眼；基础帧停留可在 2–5 秒内随机，不机械循环眨眼 |
| `receive_w` | 6 | 看向摊主、移重心、伸近翼、保持递杯位置、收翼、回稳；杯由独立关卡道具跟随 |
| `turn_w_ne` | 4 | 从柜台转向离开路线 |

每组六帧行走以 `R 接地 → R 承重 → L 摆过 → L 接地 → L 承重 → R 摆过` 为节拍。`walk_contact_guide.png` 只是足点示意图，不是角色美术。建议 90 ms/帧，约 0.54 s 一轮，世界位移初值约 30 单位/轮。程序须依据实际脚落点调节根节点位移和帧相位：支撑脚在屏幕上停住，身体越过它；不能单独平移完整图片然后在帧切换时让脚滑。速度、时长是首轮调试值，验收以脚接地效果为准。

## 生产顺序与审核关口

1. **角色定型**：画一张同尺寸的方向设定表，至少有 N、NW、NE、W 四视图；确认眼/喙比例、背心和挎包在各方向的实体连续性、120 单位身高和脚点。此阶段只审核 79/127 px 小样，未通过不展开 36 帧。
2. **接地关键帧**：每个走向先画第 00 帧和第 03 帧，并画 `turn_nw_w_00/03`、`receive_w_02/03`。把这些关键帧放进灰盒路线中，看后背、朝向、挡住柜台的位置和杯的交接点。
3. **补齐中间帧**：按同一个设定表手画其余帧。所有帧色块与服装接缝固定，羽毛纹理可以轻微活跃，但不得随机换花纹/改变包扣/鸡冠齿数。头、翼、腿的动作须和移重心一致。
4. **导出与验收**：从 `.ora` 导出 36 张同画布 PNG，核对命名、Alpha、注册点、颜色、帧时长，再由关卡代码接入。当前只有空白模板和清单，**没有**可导入角色帧。

画完后把 36 张 PNG 放入同一个导出目录，运行 `python art/production/courier_chicken_v1/validate_and_preview.py <导出目录>`。脚本仅在 36 张均存在、均为 256×256 RGBA 且画面未触边时，生成各动作的 79/127 px GIF 回放；缺帧时会列出缺失文件并拒绝生成预览。最终还须在 Cocos 中检查沿真实路线移动时的脚滑与遮挡。模板生成源 `make_template.py` 可重建空白 `.ora`、引导图和 CSV，但请勿在画师开始作画后把重建模板覆盖到已绘源文件。

## 美术与运行验收

- [ ] 四个方向为同一只原创鸡；背心、包和鸡冠不因视向而消失或换侧。
- [ ] 36 张 PNG 实际存在，均为 `256×256` RGBA，命名与 CSV 一一对应，无漏帧、重复帧、导出引导线或白底。
- [ ] 每帧脚接地参考点完全一致；角色站在同一地图点时身体不会突然跳动；支撑脚在正常比例下滑移不超过约 2 屏幕像素。
- [ ] 79 px 常态和 127 px 放大下仍认出头向、翅膀动作与包，细羽纹不闪烁成噪点。
- [ ] 转身有头/胸/脚依次变化；递杯时翼尖与杯中心在最大缩放下对齐误差不超过约 3 屏幕像素。
- [ ] 10 秒无操作回放中走路、停顿、眨眼和交换杯各有因果；不会在固定 1–2 秒节拍上反复整图跳变。
- [ ] 与柜台、前景遮挡物按脚点排序；不会脚踩篮筐、穿过摊位或让头被错误遮住。
- [ ] 在模拟器和手机检查缩放、拖动、点击任务，同时记录帧率和城市分包大小。

凡是只完成参考立绘、空白 `.ora` 模板、或者工程灰盒的阶段，均不能勾选“美术与运行验收通过”。

格式依据：[OpenRaster 文件布局](https://www.openraster.org/baseline/file-layout-spec.html)、[Krita 的 ORA 说明](https://docs.krita.org/en/general_concepts/file_formats/file_ora.html)。本机未安装 Krita，当前只完成 ORA 内部结构和 PNG 尺寸自检；需在画师环境中打开一个模板并导出一个试验帧，才能声称已做绘画软件兼容性实测。
