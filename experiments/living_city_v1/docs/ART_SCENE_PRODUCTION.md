# 城市寻物场景生产标准（试产）

本文件把 [项目目标](PROJECT_SPEC.md)、[视觉规范](ART_BIBLE.md)、[资产规格](ASSET_SPEC.md) 落成一座可探索城市的制作顺序。目标是**细节密集、能观察小鸡生活、需要寻找物品**的 2D 场景。当前冬日街市的单张背景、透明角色和物品只用于机制试验；能点击和计数不等于美术通过。

2026-09-27 用户提供的[目标视频观察](TARGET_VIDEO_GAP_ANALYSIS.md)进一步明确：城市画面按**近俯视、连续街区、近似平行投影**组织，先见到可逛的商店、道路、绿地和细碎日常活动，再从中寻找目标。水彩鸡画风继续使用；目标视频中的猫、平涂着色和具体 UI 不是本项目的生产素材。当前冬日街市透视风景画不能只靠追加贴图变成这种地图，需要重新设计场景构图和分层。

## 表现技术选择

正式画面仍由 2D 纹理显示；关键是**在制作源文件中保留可编辑结构**，让角色、物品、建筑前景、阴影与地面各有恰当的层。街区可由一张统一画好的底层加若干可遮挡的建筑/摊位层组成，也可由同一美术规范下的模块组合；两种方式都要在相机里检查接缝和笔触。角色优先用少量绘制姿态的逐帧动画，必要时把头、翼、腿、衣装拆为 2D 部件做节点/骨骼动画。可复用的 SpriteFrame 或图集仍是正常游戏资源，不能把「贴图」本身视为错误；错误是独立图像未经同场景设计和合成就直接平铺。

不以 3D 建模为默认工序。3D 灰模可用于建筑透视、道路布局或光照参考，某些寻物项目也先渲染再做 2D 上色；但本项目目标镜头固定在近俯视 2D，首个生产切片不需要模型、材质和 3D 动画管线。只有当 2D 实作无法解决明确的布局或重复生产问题时，再评估局部 3D 辅助。见文末制作依据。

## 1. 先设计一次可玩的寻找，再画正式场景

1. 在 `mapSize` 对应的画布上做灰度白盒：标出道路、建筑、摊位、远中近景、停留点、可走区、不可走区、遮挡区、镜头边界。先在 Cocos 中验证拖动、缩放和可到达的搜索区域。
2. 给每个目标写放置单：`目标 ID / 叙事线索 / 所属摊位或角色 / 世界坐标 / 可见部分 / 遮挡物 / 预期搜索距离 / 点击区域 / 提示内容`。难度来自融入环境、局部遮挡和观察行为，不能只靠缩到几像素、降低对比度或任意藏在纹理噪声里。
3. 先用纯色占位物实测寻找流程：全图看不到过分突兀的“贴纸”；放大到正常搜索尺度后能凭轮廓和线索找到；触控区域足够大且与邻近角色、物品不冲突。记录真实手机的寻找时间和误触，再决定位置与难度。
4. 对每件目标指定一个合理归属。例如铜铃挂在灯摊，蓝手套夹在邮差包边，陶哨混在陶匠货架。目标本身保留独立资源和任务 ID，以支持点击、状态变化及复用；视觉上由场景层、投影、接触关系和遮挡把它放进去。

## 2. 场景必须按空间组织成层

场景源文件至少保留可单独导出的：远景与天空、建筑主体、地面和街道、摊位及陈列、后景遮挡、前景遮挡、动态装饰、交互目标。大场景可按街区分块，但接缝、地面线、透视和照明必须连续；不要把每块当作独立海报随机生成。

在每个可玩街区标注鸡的足点、行走带、站位、前后关系及障碍边界。角色脚下的接触阴影由运行时或同一光照规则合成，不在透明角色图里烘焙一块与地面不符的阴影。角色与摊位/树/柜台的遮挡使用明确的层级或遮挡片；移动时按足点所属的街区深度槽排序，不能只靠全图一个固定 `zIndex`。被遮挡的目标，其点击区域应对应可见部分，不能隔着不透明前景点击到隐藏内容。

交付场景前要在设计图上画出三种关系：**鸡能走到哪里、哪里会被挡住、玩家能看见并点击哪里**。若一张平面背景无法拆出正确的遮挡片，应回到场景设计或局部重绘，不再通过整图模糊、锐化、调色掩盖层级问题。

## 3. 先统一画风，再制作角色和动作

所有资产遵循 [视觉规范](ART_BIBLE.md)：地图近俯视且近似平行投影，角色可有轻微 3/4 转身，统一暖棕手绘线、纸面水彩与干笔纹理、中低饱和色、左上柔光。鸡的头身、羽毛结构、脚爪和衣装遵循同一获批母版；目前只有画风参考获批，角色母版尚未获批。背景里的鸡、可点鸡和独立物件必须在同一视角、比例和光照下共同审图。

制作角色先在场景截图上确认足点、身高和遮挡，再产出动作。重点角色至少准备与行为对应的少量真实姿态或可动分层：走路要有交替脚步与重心变化，啄食要有头颈下探，眨眼/探头/抱物要有可读的动作变化；Tween 用于节奏和位移，不能用整张立绘平移加上下浮动代替全部动作。保持锚点、轮廓体积、衣装和手持物在各帧一致。先做 1–2 名重点角色的完整动作样张，再扩展同族谱角色。

场景里的远处群演可画入远景或单独的静态层，局部加入灯笼摆动、蒸汽、招呼等低成本循环。近处重要小鸡和任务小鸡使用可交互的独立角色，其中一部分持续或间歇移动；不要把 20 张静止立绘一起横移当作“活着的街市”。移动路线遵守可走区和遮挡，停顿、转身、互动有不同节奏。

## 4. 源图与游戏文件分开验收

每个资产 ID 保留生成提示词、原始源图、处理脚本或参数、导出尺寸、Alpha/色彩检查、文件哈希、游戏截图和审核结论；状态写入 `art/asset_manifest.json`。源图分辨率是 **Generation Spec**，导入 Cocos 的尺寸、格式和字节预算是 **Final Game Asset Spec**，不得把低分辨率源图插值放大后称为增加了细节。

背景和街区按游戏中的最大有效放大倍率选择原生细节与切片尺寸；角色/物品按最终屏幕显示大小制作，不以 256×256 文件尺寸保证清晰。透明层检查边缘和真 Alpha；不透明层检查接缝、压缩纹理与伪文字。场景贴图按城市 Bundle 组织，记录纹理总量、构建后的首包/资源包大小、手机内存和加载时间；压缩或切片以真机画质与性能共同决定，不先定死 JPG/WebP/PNG。

## 5. 最小生产切片与放大条件

先完成冬日街市中**一个有摊位、道路、前景遮挡的完整街区**：一处走动和停留的小鸡、一处静态/低成本群演、一件嵌入环境的任务物品，以及相应线索。该切片用于验证统一画风、足点、真实动作、遮挡和寻物难度；通过后按相同规则扩展整座城市，而不是把切片当成完整城市交付。

切片要在 Cocos 真实镜头、普通手机和微信开发者工具中审查：

- [ ] 初始视图、常用放大倍率、最大放大倍率下，背景既不锐化起白边，也不糊成无法寻找的纹理。
- [ ] 鸡和物品的线条、颗粒、颜色、光线、比例属于同一个场景；脚落在地面，走动时不穿过屋顶、柜台或树干。
- [ ] 重点鸡至少可看出真实姿态变化和停顿行为，远处群演不出现同步机械摇摆。
- [ ] 目标在所属场景中可发现但不一眼跳出；线索有效，点击区域与可见部分一致，拖图/缩放不误计数。
- [ ] 图层接缝、Alpha 边缘、遮挡顺序、任务反馈、加载和手机帧率均通过实际运行检查。
- [ ] 源图、提示词、处理记录和失败样张留档；审核结论与清单状态一致。

完整 Demo 仍应达到 [项目规范](PROJECT_SPEC.md) 的目标：一座大型城市、至少 10 个静态隐藏物、5–8 只鸡，覆盖至少 3 种行为；任务中至少 3 个物品目标和 2 个小鸡目标。当前 [`city_demo/city.json`](../assets/bundles/city_demo/city.json) 只有 3 件物品、`chickens: []`，运行时另有试验性群演。它证明部分机制可用，**尚未达到内容量与美术验收门槛**。当前资产保持 `review`，不能标记为正式获批。

## 制作依据

- [Hidden Folks 开发者访谈](https://medium.com/@stefanlesser/behind-the-game-hidden-folks-e6198dfa885a)：其搜索目标结合线索、动作与互动；场景对象需要明确的 2D 层级。该项目的做法提供方向，不能直接代替本项目的试玩验证。
- [寻物游戏 2D 场景美术制作记录](https://www.gamedeveloper.com/design/the-making-of-a-hidden-object-game-2d-background-art)：作者明确区分把物件合理放入场景与在平面图上隐藏图标，并在最终绘制中处理光照、遮挡和材质。
- [Cocos Creator 3.8 2D 排序文档](https://docs.cocos.com/creator/3.8/manual/zh/engine/rendering/sorting-2d.html)及[动画帧 API](https://docs.cocos.com/creator/3.8/api/en/class/AnimationClip)：引擎具备实现图层顺序和精灵帧动画的能力；是否采用 Sorting2D 组件或现有节点排序，由实际渲染和包体测试决定。
