# 活街区制作方式修正（2026-09-28）

## 这次试玩确认的问题

`winter_market_block_trial_001` 的拖动、缩放、点击和任务可运行，但用户试玩后判定角色与街道仍有明显“死人贴图感”。运行画面和代码复查显示：

- 小鸡的头、翅、腿、眼和衣物烘焙成完整 PNG。两张姿态图分别生成，细节会跳；代码中的分层节点在加载 PNG 后被关闭。
- 原信使只在约 61 地图像素内横向往返，摊主按固定时间整图切换“倒茶”；二者的动作没有构成一个场景事件。
- 背景是一张完整的透视街景插画。柜台前没有足够的石板路站位，花桶、推车与长凳占据服务区；逐次移动 NPC 坐标无法产生可信的“买茶”互动。
- 一个竖屏首屏里活动角色太少；大片建筑和道具完全静止。新增一缕蒸汽或整图轻微摆动只会做局部补救。
- 内置图像生成试产的两张分层角色源图均未过关：一张含错误部件，另一张只有头/身体且颈部露缝、腿翼仍烘焙。详见 `art/review/winter_market_life_trial_002/QA.md`。

因此本街区仍是**玩法与资源管线试验**，视觉验收未通过。不能以继续增加完整角色贴图或给整图加位移作为正式内容生产方法。

## 下一块街区先制作可玩的空间

1. **灰盒关卡**：在 Cocos 用简单形状先定近俯视镜头、路面、店面、摊位、可走多边形、入口/出口、顾客和摊主的足点、任务物放置点。先让角色走到摊位、停下、互动、离开；路径与柜台、车、花桶不相交，再画正式图。
2. **同一空间中的美术层**：按固定镜头与尺寸绘制地面、建筑背部、柜台与物件、可走角色、屋檐/栏杆/花桶等透明前景、局部特效。所有层共享同一地图坐标与水彩线条/光源，不靠一张背景图后续切洞补遮挡。
3. **角色母版与动作**：先审核一只游戏尺寸的幼鸡母版；以它为源绘制身体、头、近/远翼、双腿、眼、服饰/道具等有隐藏重叠区的透明层，记录锚点。用 Cocos 2D 节点完成脚点锁定的待机/眨眼、走路接触姿态、转头和一项场景动作。只有动作小样在约 60–100 px 的实际显示高度仍可读，才扩展角色族谱。AI 生成可用于草图；不能把未经补画的“拆件图”直接认作可用骨骼资源。
4. **场景生活节奏**：每个活动角色有区域、目标点、停留、面向、动作及间歇；摊位动作由到达/交互事件触发。背景中的灯笼、蒸汽、布幌等仅在有独立层和合理锚点时运动。目标物与所属摊位/角色有接触、遮挡和搜索线索，避免明显悬浮在画面上。
5. **逐级验收**：先看一块街区 10 秒无操作回放，再检查拖动/放大、点击与任务、同路人遮挡、手机帧率。至少确认角色脚不滑、动作不跳纹、互动位不被道具占据、普通缩放下能读懂角色在做什么，才把该切片作为后续城市模板。

这是 **2D 分层绘制与场景编排** 的流程；目前没有证据表明为实现目标必须建 3D 模型。当前任何候选图与新代码都保持 `review`/试验状态，直到用户在实际运行画面上确认方向。
