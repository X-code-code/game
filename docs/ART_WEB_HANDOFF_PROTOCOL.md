# Codex → ChatGPT Web 美术交接协议

适用项目：鸡仔城市探索微信小游戏。此协议记录于 2026-09-27，作为**交给 ChatGPT Web 生成时**的执行细则。原角色分工是 Codex 分析、拆批、编写任务包、验收及后处理，ChatGPT Web 生成源图，用户负责复制任务包与上传参考。用户随后明确授权 Codex **直接生成并接入初版美术**；这轮执行内置图像生成与项目验证，不等待 Web，仍保留本协议作为日后 Web 交接的可选流程。

## 当前依据和事实

- 总规范：`docs/PROJECT_SPEC.md` 第 13、19–31、49 节。游戏为原创、温暖、轻绘本手绘感的 2D 城市探索；小鸡素材最终需要身体、头、眼、嘴、翅膀、腿、配饰等独立层；独立道具应透明、不裁边；城市场景采用轻微 3/4 俯视；背景、前景遮挡及可交互元素要分层。
- 可行性审查：`docs/PROJECT_FEASIBILITY_REVIEW_2026-09-26.md`。当前城市和小鸡仍由代码画出占位图，`demo_*` 字符串尚未映射到正式图片；单张完整鸡参考图不能直接支撑现有头部/闭眼动画。
- 当前两个 `CityConfig` 是 `demo_city` 与 `harbor_test`。分别含香蕉、包裹、钥匙、小鸡等测试对象；第二城也是程序占位图。项目中尚无 `art/reference/chicken_master_reference.png`、正式背景或可导入游戏的获批精灵，不能虚报完成。
- 用户于 2026-09-27 选定 `art/reference/chicken_cast_style_guide_v1.png` 为**画风方向参考**，已在 `art/asset_manifest.json` 按此范围批准。图中八角色的具体设计、服装与排版并未被批准为游戏资源。第一张候选小鸡已存 `art/generated/chicken_master_reference_001/source_01.png`，审核为不采用，记录在 `art/review/chicken_master_reference_001/REVIEW.md`。
- `docs/ART_BIBLE.md` 已按用户选定的水彩角色群风格修订，`docs/ASSET_SPEC.md` 仍为试产参数。画风方向选定不等于鸡母版比例、城市样张或各透明层已定稿；应在游戏内缩图与真机实测后固定。

## 每次交接的执行顺序

1. 读取总规范、美术规范、当前城市 JSON、全局素材清单及获批参考图。逐项标注：已批准、待审核、缺失、仅代码占位、需要复用。不要把代码占位视为正式资产，也不要重复请求已可复用的资源。
2. 按依赖拆批：先鸡母版试产与确认，再做一张穿衣角色小样检验角色群气质，然后制作分层鸡组件、城市风格小样、前景/道具、UI。角色每批 1–4 个设计，复杂场景 1–2 张，独立道具/配饰每批约 6–12 个；试产可更小且须说明目的。
3. 每个实际批次创建 `art_requests/<batch_id>/`，其中固定文件为 `01_WEB_PROMPT.md`、`02_MANIFEST.json`、`03_ACCEPTANCE.md`。如依赖任何已批准图、色板或参考场景，必须增建 `04_REFERENCES.md`，逐一列出项目绝对路径、要上传的文件名、用途及缺失时处理方式。
4. `01_WEB_PROMPT.md` 是**可直接复制**到 ChatGPT Web 的完整任务。它必须独立写出项目背景、视觉规则、逐项资源、数量、构图、视角、透明要求、画面比例、生成推荐尺寸、最终游戏目标尺寸、安全边距、阴影、文字、命名、禁止项、验收要求与“请实际生成图片”的指令。不能写“沿用之前的风格”等需要对方查看本地工程的句子。
5. `02_MANIFEST.json` 使用英文 snake_case 的稳定 `id`/`filename`，记录 `batchId`、`styleId`、`total`、资产类别、描述、参考图依赖和 `generationSpec` / `finalGameAssetSpec`。新资源的 ID 全局唯一；若同一资源重做，批次以 `revisionOf` 指向包含该 ID 的旧批次并沿用原 ID，不把新版本伪装成新资源。`total` 等于各项 `quantity` 之和。概念参考图可设 `targetGameSize: null`，同时明确它的最终参考图存放规格；这表示尚不导入游戏。
6. Web 生成后，Codex 核对数量和内容，并进行裁切、统一画布、缩放、Alpha 边缘检查、转换 PNG/WebP/JPG、压缩、统一命名、校验文件尺寸。只能对实际源图做这些操作；不能在任务包里宣称后处理已完成。
7. 人工审核后更新全局 `art/asset_manifest.json` 中的状态。流程为 `draft → review → approved` 或 `rejected`。保留源图、修改版本及来源；只有 `approved` 资产才可作为后续批次的固定参考或进入正式资源映射。对每批生成 contact sheet，并在游戏实际尺寸上验证辨识度。

## 格式与一致性规则

- 批次 ID 使用 `snake_case`，例如 `chicken_master_reference_001`；目录内文件名按本协议固定。`art_requests/_template/` 是空白工作模板，不是可以直接发送的批次。
- `styleId` 暂定 `chicken_trip_v1`，设计状态为**草案**。用户选择的角色群图已成为这个草案的画风锚点，母版与城市场景仍须分别审批。母版获批后记录版本，不悄悄改变后续批次比例、线条、视角与光源。
- 每份提示词写明是否需要上传参考图。需要时，提示词也要列出文件名与用途；`04_REFERENCES.md` 给用户操作清单。参考图不在项目中时，标记依赖未满足，不能假装 ChatGPT Web 已看到。
- 图像模型负责高质量源图；像素尺寸、Alpha 与编码格式由后处理验证。提示词中的推荐生成尺寸属于 **Generation Spec**；最终导入的精确尺寸、格式与命名属于 **Final Game Asset Spec**。
- 参考图里不能嵌入完整游戏场景的可交互物或把遮挡层直接烘焙进背景。物品和小鸡分层后应能独立点击、移动、缩放、隐藏及替换。视觉验收必须同时看源图和缩小后的游戏目标尺寸。
